# Reference and attribution
An architectural reference was an Azure DevOps repository titled "Jedis",
linked at https://dev.azure.com/ChaitanyaDSharma/Codecrafters/_git/Jedis. The link
identifies the referenced repository; it does not establish authorship or license.
Review findings: architectural separation, basic RESP parsing, replication handshake,
transactions, limited tests and fragility in byte framing/ordering. The reference
archive had no LICENSE file. We must NOT copy, mechanically translate, or include the
Java source unless permission is verified. Official public protocol and command
specifications guide the supported behavior. Independent verification of source
provenance, attribution, licensing and security remains a release requirement.

Primary behavior references:
- https://redis.io/docs/latest/develop/reference/protocol-spec/
- https://redis.io/docs/latest/develop/using-commands/transactions/
- https://redis.io/docs/latest/management/persistence/
- https://redis.io/docs/latest/manual/replication/
- https://redis.io/docs/latest/commands/

'PyRedis Engine' is an independent educational project, not associated with or endorsed
by Redis Ltd or its contributors.
